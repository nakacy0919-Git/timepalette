# TimePalette Mission Creator — 管理者の投稿審査・公開フロー（開発版）

## 目的
他の先生が提出したミッションを管理者が国・カテゴリーを横断して確認し、承認後に一括公開する。
先生が編集中の `draft` は一括承認対象に含めない。

## 操作
1. 管理者の4桁コードでMission Creatorにログインする。
2. 左側「投稿の審査・公開」を開く。初期フィルターは「提出済み」。
3. 「1. 投稿を確認」で問題一覧を開く。国・カテゴリー・作成者・形式・キーワードを絞り込める。
4. 各問題をクリックして正答・写真・出典・教材内容を確認する。
5. 一括承認する問題にチェックを付ける（1回30件以内）。「選択した提出済みを一括承認」を実行する。
6. 一括結果に失敗があれば問題ごとの理由を確認する。通信タイムアウト時は自動再実行せず、一覧を更新して状態を確認する。
7. 「2. 公開待ち」（または一括承認結果の「次へ」）へ進む。対象を選択し、画像・文章・公開権利を確認して公開する。
8. 公開先は投稿ごとの `countryIso` / `domain` に基づく。別の国やカテゴリーを手動指定する必要はない。
9. 「3. 公開中」で公開状態を確認。公開順の変更・停止は従来の「公開ミッション管理」から行う。
10. 「新しい投稿を取得」で他の先生の追加分を再読み込みする。件数が多い場合は100件ずつ追加表示する。

## 自動テスト対象
- `tests/missionCreator-bulk.test.mjs`: 提出済みのみ一括承認、下書きは拒否、管理者以外は拒否、最大30件、国・カテゴリーの自動判定、部分失敗後も継続。
- `tests/missionCreator-bank-filters.test.mjs`: ステータス・検索・国・カテゴリーの組み合わせ。
- 推奨実行: `node --test tests/missionCreator-bulk.test.mjs tests/missionCreator-bank-filters.test.mjs`。
- Vercel Previewで `npm run build` に含まれる既存テストとViteコンパイルを確認する。

## 本番反映前の手動受入検査
- 管理者でログインした際「提出済み」が初期表示されること。
- 先生の提出済み問題を一覧から複数件選べること。
- 下書きを一括承認できないこと。
- 問題の詳細で写真・出典・正答を確認できること。
- 承認後に「公開待ち」に現れること。
- 公開後に本人の国・カテゴリーに問題が反映されること。
- 画像不足・公開非対応形式などで失敗した場合、問題ごとのエラーが表示されること。
- 一覧が200件を超えても追加表示できること。
- iPad Safariで段階カード・絞り込み・ボタンが表示されること。

## 環境と注意
- Vercel Previewは現在Google側バックエンドを使用する設定で、本番はCloudflare D1+R2。プレビューのビルド成功は本番Cloudflareでの管理者ログイン・書き込み動作の証明ではない。
- 管理者の承認・公開APIは既存の権限制御を引き続き使用。一般教師に権限を追加していない。
- このブランチだけを変更し、`main`へのマージや本番へのデプロイは行わない。
